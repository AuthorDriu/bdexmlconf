# bdexmlconf

Утилита командной строки для преобразования файлов конфигурации Borland
Database Engine (BDE) — `IDAPI.CFG` / `IDAPI32.CFG` — в XML и обратно.

Двоичный формат BDE непрозрачен, его трудно просматривать и править вручную.
`bdexmlconf` представляет его в виде читаемого дерева XML, позволяет
редактировать и сравнивать конфигурацию обычными текстовыми инструментами и
записывает её обратно без потери данных.

*English version: [README.md](README.md).*

## Возможности

- **`export`** — прочитать двоичный файл конфигурации BDE и записать его в XML.
- **`import`** — превратить XML-документ обратно в двоичный файл конфигурации BDE.
- **`merge`** — объединить две XML-конфигурации: *minor*-файл вливается в
  *major*, и при конфликте побеждает major.
- **Отсутствие потерь по умолчанию.** Кодировка `raw` (по умолчанию)
  гарантирует, что `export` с последующим `import` воспроизведёт файл байт в
  байт, включая текст в устаревших кодовых страницах.
- **Явное управление кодировками.** Отдельно задаётся кодировка XML-файла
  (`--encoding`) и кодировка текста внутри двоичного файла (`--bde-encoding`).
  Кодовые страницы принимаются по имени (`windows-1251`, `cp866`) или номеру
  (`1251`, `866`).
- **Автоопределение кодировки.** При `import` и `merge` кодировка XML
  определяется по BOM или по объявлению XML, если не задана явно.
- **Безопасная запись.** Выходные файлы пишутся атомарно (во временный файл с
  последующим переименованием), а существующий файл сохраняется в резервную
  копию и восстанавливается при любой ошибке. `import` отказывается
  перезаписывать существующий файл без флага `--rewrite`.
- **Интеграция с Windows.** Если путь не задан, активный файл конфигурации
  находится через реестр (`CONFIGFILE01` в
  `SOFTWARE\Borland\Database Engine`), а при его отсутствии — в стандартных
  каталогах установки. `import --set-default` прописывает новый файл в реестр.

## Требования

- Инструментарий Rust (проект использует редакцию 2024, то есть Rust 1.85 или
  новее). Код регулярно собирается свежими стабильными версиями.

## Использование

```
bdexmlconf <КОМАНДА>
```

Доступные команды: `export`, `import`, `merge`.

### `export`

Читает файл конфигурации BDE и записывает XML-документ.

```sh
bdexmlconf export -i IDAPI32.CFG -o idapi.xml
```

| Опция                    | По умолчанию | Описание                                                             |
| ------------------------ | ------------ | -------------------------------------------------------------------- |
| `-i, --input <PATH>`     | —            | Читаемый файл BDE. Если не задан, путь определяется системой.        |
| `-o, --output <PATH>`    | —            | Записываемый XML-файл. **Обязательна.**                              |
| `-e, --encoding <ENC>`   | `UTF-8`      | Кодировка XML-файла.                                                 |
| `--bde-encoding <ENC>`   | `raw`        | Кодировка текста внутри двоичного файла BDE.                         |

### `import`

Читает XML-документ и записывает файл конфигурации BDE.

```sh
bdexmlconf import -i idapi.xml -o IDAPI32.CFG
```

| Опция                    | По умолчанию | Описание                                                               |
| ------------------------ | ------------ | ---------------------------------------------------------------------- |
| `-i, --input <PATH>`     | —            | Читаемый XML-файл. **Обязательна.**                                    |
| `-o, --output <PATH>`    | —            | Записываемый файл BDE. Если не задан, путь определяется системой.      |
| `-e, --encoding <ENC>`   | авто         | Кодировка входного XML. Определяется по BOM/объявлению, иначе UTF-8.   |
| `--bde-encoding <ENC>`   | `raw`        | Кодировка текста внутри двоичного файла BDE.                           |
| `--set-default`          | выкл.        | Сделать записанный файл файлом по умолчанию в реестре Windows.         |
| `--rewrite`              | выкл.        | Перезаписать существующий файл BDE. Без него запись в существующий файл прерывается. |

`--set-default` имеет смысл только в Windows; на других платформах он
завершается ошибкой.

### `merge`

Вливает minor-конфигурацию XML в major.

```sh
bdexmlconf merge -M base.xml -m overrides.xml -o merged.xml
```

| Опция                     | По умолчанию | Описание                                                               |
| ------------------------- | ------------ | ---------------------------------------------------------------------- |
| `-M, --major <PATH>`      | —            | Major-файл (базовый) XML. **Обязательна.**                             |
| `-m, --minor <PATH>`      | —            | Minor-файл XML. **Обязательна.**                                       |
| `-o, --output <PATH>`     | —            | Записываемый объединённый XML-файл. **Обязательна.**                   |
| `--major-encoding <ENC>`  | авто         | Кодировка major-файла (определяется, если не задана).                  |
| `--minor-encoding <ENC>`  | авто         | Кодировка minor-файла (определяется, если не задана).                  |
| `-e, --encoding <ENC>`    | `UTF-8`      | Кодировка выходного XML-файла.                                         |

Правила объединения:

- Переменные и контейнеры сопоставляются **по имени** на любом уровне
  вложенности.
- При конфликте сохраняется значение из **major**-файла.
- Записи, которые есть только в minor-файле, добавляются в результат.
- Контейнеры, присутствующие в обоих файлах, объединяются рекурсивно.
- Порядок записей major-файла сохраняется; добавленные записи minor
  дописываются в конец.

### Коды возврата

| Код  | Значение                                                                 |
| ---- | ------------------------------------------------------------------------ |
| `0`  | Успех.                                                                    |
| `1`  | Ошибка времени выполнения (ввод-вывод, разбор, кодировка, …); подробности в stderr. |
| `2`  | Ошибка командной строки (неизвестный флаг, пропущен аргумент, …).         |

## Формат XML

XML-документ повторяет дерево, хранящееся в файле BDE:

```xml
<?xml version="1.0" encoding="UTF-8"?>
<bde-config version="1">
  <container name="IDAPI">
    <variable name="VERSION" value="5.0"/>
    <container name="ALIASES">
      <container name="MyAlias">
        <variable name="PATH" value="C:\Data"/>
        <variable name="DRIVER" value="PARADOX"/>
      </container>
    </container>
  </container>
</bde-config>
```

- Корневой элемент — `<bde-config>` с атрибутом `version`.
- `<container name="…">` группирует переменные и вложенные контейнеры.
- `<variable name="…" value="…"/>` — отдельная пара имя/значение.
- Порядок записей важен и сохраняется точно.

Полный пример см. в [`examples/idapi.xml`](examples/idapi.xml).

## Кодировки

Задействованы две независимые кодировки:

- **Кодировка XML** (`-e/--encoding`) — как хранится сам XML-документ. Имена
  разрешаются по набору меток WHATWG; принимаются и «голые» номера кодовых
  страниц (`1251` → `windows-1251`, `866` → `cp866`).
- **Кодировка BDE** (`--bde-encoding`) — как хранится текст внутри двоичного
  файла BDE. Указывайте конкретную кодовую страницу (например `windows-1251`
  или `cp866`), если известно, что файл её использует.

Значение по умолчанию `--bde-encoding raw` — это отображение ISO-8859-1 без
потерь, где каждый байт соответствует тому же коду Unicode. Оно делает
круговой цикл точным для любого байта, но не может представить символы выше
`U+00FF` — в этом случае нужна реальная кодовая страница. Если выбранная
кодовая страница не может представить какой-то символ, выводится ошибка, а не
тихая потеря данных.

## Особенности платформ

**Windows.** Если `-i`/`-o` не заданы, утилита ищет активный файл конфигурации
в реестре по пути
`HKEY_LOCAL_MACHINE` / `HKEY_CURRENT_USER\SOFTWARE\Borland\Database Engine`
(значение `CONFIGFILE01`), а затем переходит к обычным каталогам установки
`Common Files\Borland Shared\BDE`. Команда `import --set-default` записывает
новый путь обратно в реестр.

**Linux / macOS.** Доступ к реестру отсутствует, поэтому пути ввода и вывода
нужно задавать явно; `--set-default` отклоняется.

## Как устроен двоичный формат

Файл BDE — это поток записей с тегами, разделённых NUL-байтами:

```text
начало записи        : 0x03 0x00
запись контейнера    : 0x00 <name> 0x01 0x00
запись переменной    : 0x01 <name> 0x04 <value>
конец блока          : 0x02 0x00
```

Каждая строка хранится как `0x00 <байты…> 0x00`. Контейнер открывается своей
записью и закрывается маркером конца блока; самый внешний контейнер
закрывается неявно в конце файла (явный маркер тоже допускается). Парсер
принимает файлы и с завершающими маркерами, и без них, а сообщения об ошибках
содержат смещения в байтах.

## Структура проекта

```
src/
  main.rs            точка входа
  cli.rs             интерфейс командной строки (export / import / merge)
  bdeconf.rs         дерево конфигурации в памяти
  bdeconf_reader.rs  парсер двоичного формата BDE
  bdeconf_writer.rs  сериализатор двоичного формата BDE
  xmlconf.rs         преобразование Config <-> XML
  merge.rs           логика объединения
  encoding.rs        разбор и определение кодировок
  paths.rs           поиск файла конфигурации (реестр, стандартные пути)
  atomic.rs          атомарная запись с резервным копированием
tests/integration.rs сквозные тесты бинарника
examples/idapi.xml   пример конфигурации
```
